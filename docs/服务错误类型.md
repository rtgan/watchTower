# 通用错误码（common）
适用于所有服务的通用业务错误码。日志中出现这些码时按此释义排查。
- 12001：调用接口参数错误（如类型不匹配、必填字段缺失）。排查入参校验日志。
- 12002：数据库更新失败（数据库问题，建议排查日志与慢查询）。检查 DB 连接池、主从延迟、死锁。
- 12003：下游接口错误（下游接口报错或不可用）。检查下游服务健康状态、网络连通性。
- 12004：实例不存在（上游传了错误的实例 id）。校验上游传入的实例 id 是否有效。

# order-service 订单服务错误码
订单服务负责下单、订单状态流转与库存扣减。
- 22001：库存不足（下单时库存扣减失败）。排查库存服务返回，确认是否超卖。
- 22002：订单状态非法（订单状态机校验失败，如已支付订单再次发起支付）。
- 22003：订单创建失败（调用下游 payment-service 失败）。常伴随通用码 12003，需排查下游支付服务。
- 22004：订单查询超时。排查数据库慢查询或缓存击穿。

# payment-service 支付服务错误码
支付服务对接第三方支付通道，是 order-service 的下游。
- 32001：支付通道超时（第三方支付通道响应超时）。检查第三方通道状态与网络。
- 32002：支付金额不匹配（下单金额与支付金额不一致）。排查金额计算与上游传参。
- 32003：支付服务不可用（服务自身宕机或依赖的 DB 不可用）。若 order-service 报 12003，多由此引起。

# user-service 用户服务错误码
用户服务负责用户鉴权与用户信息查询。
- 42001：用户不存在（查询的用户 id 在库中不存在）。
- 42002：用户状态异常（如账号被冻结 / 注销）。
- 42003：鉴权失败（token 无效或过期）。

# 对账服务 reconciliation-service 错误码
对账服务负责上游与下游的数据比对与差异补偿。
- 52001：对账差异（上游与下游笔数 / 金额不一致）。结合 reconciliation 日志定位差异订单。
- 52002：补偿重放失败（差异订单重放下游失败）。常伴随 12003，需先恢复下游服务。
- 52003：对账数据源不可用（读取上游 / 下游数据源超时）。
